# AGENTS.md — правила роботи ШІ-агентів з Wall Protocol

Цей файл є обов'язковою інструкцією для будь-якого ШІ-агента, який змінює проєкт.

## 1. Головне правило

Не ламати структуру GameMaker заради швидкого редагування. Перед змінами ресурсів перевіряти формат поточної версії GameMaker та надавати перевагу офіційній документації YoYo Games.

## 2. Кодування і назви файлів

- Усі текстові файли: UTF-8 без псування кирилиці, LF.
- Технічні каталоги GameMaker (`objects`, `rooms`, `scripts`, `sprites`, `folders`, `options`) не перейменовувати і не локалізувати.
- Не створювати посилання на вигадані шляхи на кшталт `folders/Скрипти.yy`.
- Українська дозволена в Markdown, коментарях та тексті інтерфейсу, але імена ресурсів/змінних краще залишати латиницею.

## 3. Робота з `.yyp` / `.yy`

- Не видаляти службові поля GameMaker і не змінювати `resourceVersion` навмання.
- Якщо створюється ресурс, він мусить мати коректний `.yy`, фактичні супровідні файли та запис у `Wall Protocol.yyp`.
- Якщо ресурс додається в кімнату, `objectId`, `instanceCreationOrder` та `instances` повинні посилатися на реальні файли.
- Після ручного редагування метаданих перевіряти їх JSON5-парсером або в GameMaker Project Health.
- Не створювати спрайт-ресурс без усіх PNG/sequence-файлів, які очікує GameMaker.

## 4. Архітектура поточної вертикальної версії

Зараз гра навмисно мінімалістична за структурою: `obj_game` містить ігрову логіку та процедурний рендеринг. Це зроблено, щоб швидко мати стабільну портфолійну вертикальну версію без десятків крихких ресурсів.

Файли:
- `objects/obj_game/Create_0.gml` — конфіг, дані, допоміжні функції, reset/build/upgrade/spawn.
- `objects/obj_game/Step_0.gml` — ввід, хвилі, рух ворогів, атаки веж, економіка, стани гри.
- `objects/obj_game/Draw_0.gml` — тільки відображення поля, UI та ефектів.

Не переносити важку логіку в Draw Event.

## 5. Безпечний порядок змін

1. Прочитати `README.md`, `Довідка програміста.md`, `Що треба зробити.md`.
2. Зробити точкову зміну у GML.
3. Перевірити дужки, лапки, назви функцій GameMaker та змінних.
4. Якщо змінювалися `.yy/.yyp` — окремо перевірити метадані.
5. Відкрити проєкт у GameMaker, запустити Project Health, потім Run.
6. Лише після успішного запуску позначати пункт як готовий у README/TODO.

## 6. Заборонені скорочення

- Не маскувати помилки через видалення ресурсу з `.yyp`.
- Не замінювати пошкоджені `.yy` файлами зі старих версій GameMaker без перевірки схеми.
- Не додавати зовнішні мережеві запити, телеметрію, трекери або SDK без явної потреби власника проєкту.
- Не додавати залежності, які вимагають ключів API, для базового запуску гри.
- Не робити великий рефакторинг одночасно з новою механікою.

## 7. Definition of Done для нової механіки

Механіка вважається готовою лише коли:
- проєкт відкривається без помилок ресурсів;
- гра запускається;
- немає runtime error у Create/Step/Draw;
- механіка має зрозумілий UI/feedback;
- старі механіки не зламані;
- README і TODO оновлені.
